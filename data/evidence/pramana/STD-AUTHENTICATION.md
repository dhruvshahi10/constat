# Authentication and Workspace Access Standard

Access to a workspace requires a bearer token. Tokens take the form `t.<slug>.<random>` and carry 192 bits of entropy generated by the platform's cryptographic random source. A token is displayed once, at issue, and is never stored anywhere in recoverable form.

The database stores only the SHA-256 digest of a token, never the token itself. Comparison is performed with a constant-time digest comparison, so a timing signal cannot be used to recover a valid token one byte at a time.

Every token is bound to exactly one workspace slug. The slug is carried inside the token and must equal the slug in the request path; that equality is checked before the hash comparison happens. A token issued for one workspace therefore cannot read another, and a request that omits or mismatches the slug is rejected before any credential material is examined.

The token is a high-entropy random secret compared against a stored hash. It is deliberately not described as a keyed or signed credential, because it is not one, and describing it that way would be false assurance to a reviewer.

There is no password, no password reset flow, and no shared account. Access is revoked by deleting the token record, which takes effect on the next request.
